# Build architecture

`core/domain` owns validation, official-source acquisition, isolated job directories, command execution, process-tree cancellation, log persistence, UCI checks and build manifests. `cli` calls it directly. `core/ffi` generates types from `proto/compiler.proto`, catches unwinding panics and exposes ABI version 1. `src/ChessEngineCompiler.Interop` provides LibraryImport/SafeHandle wrappers and validates request IDs. The WinUI shell owns selection, window UI, native directory pickers, appearance and exported script file assembly.

Every build creates `output/jobs/<timestamp>-<pid>-<sequence>/`. The tree contains `source/`, `build.log`, and, on success, `result/stockfish.exe`, `result/build.json`, `result/source.tar`, and upstream license/author files. Failed/cancelled job directories remain available. Builds fetch only from `official-stockfish/Stockfish`; refs and architecture names are validated. The fixed Bash wrapper forwards individual arguments and does not interpolate paths or refs into shell code. Working paths with spaces are supported. A short standalone search benchmark runs from the result folder with only the Windows system directory on PATH, verifying embedded networks and independence from MSYS2 runtime DLLs.

`Compiler::start` validates before changing job state, rejects concurrent work and launches a worker. Status and cancellation do not hold the worker's execution lock. Stdout and stderr are drained concurrently, written to disk, and bounded to a 300-line UI tail. Cancellation terminates the child process tree and waits for exit before reporting Cancelled. Tools have finite timeouts (10 minutes for source operations, two hours per make phase, one minute for UCI). Completion requires successful tool exit and both UCI markers.

ABI: `cec_abi_version`, `cec_create`, `cec_call`, `cec_result_bytes`, `cec_result_free`, `cec_destroy`. Create/call initialize output handles to null on error. Status codes are 0 success, 1 invalid/malformed arguments, 2 contained panic. Expected failures are `Response.error`. Pointers and lengths are borrowed only for calls; result bytes remain valid until Rust frees the result. Managed code copies them before disposing the result handle. Caller serializes access to each core handle and disposes it on a worker thread because destruction cancels/joins active work. A panic or transport failure stops GUI polling and requires restart. An older/newer app/core mismatch is rejected using the ABI version.

To add an engine, first define its typed configuration and a build/verify adapter behind the domain command layer. Share the process/log/job machinery, rather than assuming a Makefile or reusing Stockfish-specific CPU/backend options. Extend protobuf with new field numbers; never reuse removed numbers. Lc0 needs Meson/backend/runtime discovery and weights handling, making it a separate adapter rather than a renamed Stockfish command.
