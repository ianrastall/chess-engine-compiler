## Version 0.4.0 — Berserk

Before this change, a real Lc0 v0.32.1 CUDA build (`fd71a2d921b689c5f479d3227c3806c8e272d9c5`, Meson 1.12.1 and Ninja 1.13.2 in the documented `tools\lc0` virtual environment) was reviewed line by line. It configured, compiled, passed UCI and a 32-node cuda-fp16 search on the GTX 1660 Ti with only System32 on PATH, and saved its archives. Meson found MSYS2's pkg-config and CMake because MSYS2 is on the inherited PATH. That had no effect: lc0's `meson.build` always uses its bundled zlib on Windows, and eigen3 came from the subproject. A failed attempt beforehand was an environment fault: the saved Python had no Meson.

Real Berserk source builds used tag `14`, commit `8ae895a6151695be4a50d4fb65b0c131659c513a`, and network `berserk-9b84c340af7e.nn` (`9b84c340af7e45f6e07f0046235ccb327f4ae0840c8ee2c4b97b99121e5c5084`, recomputed and matched to its name). They used MSYS2 GCC 16.1.0 on an i7-10700, through the release CLI, in an output path containing a space. An automatic `avx2-pext` PGO build, a regular `x86-64` build and a regular `avx2-pext` build all passed. Each passed UCI and `bench 10` from its result folder with only System32 on PATH. `objdump` showed imports from only `KERNEL32.dll` and the Universal CRT. Each saved its source archive, license, manifest and full log in ignored validation jobs. The only build warnings were GCC's informational serial-LTRANS notes.

A manual smoke build first showed that upstream's `make pgo` with GCC on Windows silently applies no profiles: every translation unit reported `profile count data file not found`. The adapter therefore runs the profile steps itself with plain `-fprofile-generate`/`-fprofile-use`, and fails if GCC reports a missing profile. The validated PGO build applied all profiles. Over five alternating `bench 13` runs the PGO build averaged 1.68 M nps and the regular `avx2-pext` build 1.74 M nps, so PGO is opt-in for Berserk. The `x86-64` build ran at about 0.27 M nps; Berserk has no SIMD network path for that target.

Rust tests cover Berserk target mapping and recommendation (including the older-Zen PEXT exception), Stockfish target names being rejected for Berserk, and missing downloader tools. Managed/native checks cover Berserk defaults, typed Berserk hardware fields, plan rejection and script JSON round-trip.

`build/build.ps1` passed formatting, strict Clippy, Rust tests, managed/native integration, the real WinUI log tests and the engine-form test. That test now switches across all three engines and checks Berserk's own controls, hidden parallel jobs, its CPU target list, automatic recommendation, PGO default and retained selections. The captured Berserk form was inspected. It produced `ChessEngineCompiler-0.4.0-win-x64-setup.exe` and the supplemental zip. Ian's saved settings files hashed the same before and after an installer run.

Release verification: the full build was repeated for publication and passed all checks. Shared Jupiter.UI emitted one pre-existing CS1573 XML documentation warning; application publication succeeded. The newly built 0.4.0 installer upgraded the installed account copy; hashes of every existing settings file were unchanged. The top-level Start Menu shortcut launched the installed 0.4.0 executable (build f810385), and computer-use inspection confirmed the working Compile interface. `Get-StartApps` returned `Jupiter.ChessEngineCompiler`. Packages and checksums were published on the v0.4.0 GitHub release. No additional clean-machine or signing claim is made.
